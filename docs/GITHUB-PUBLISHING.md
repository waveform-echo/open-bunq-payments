# Publishing This Project on GitHub

The source tree is prepared so it can become a normal public repository without publishing credentials or site-specific configuration.

## Recommended first publication

1. Create an empty public repository named `open-bunq-payments` (or another non-trademark-confusing project name).
2. Push the contents of the GitHub source package, not the install ZIP.
3. Keep the independent-project disclaimer in the README and plugin description.
4. Enable GitHub Actions.
5. Enable branch protection for the default branch.
6. Enable Private Vulnerability Reporting before inviting production security reports.
7. Add maintainers/security contact details to `SECURITY.md`.
8. Run CI and require it before merge.
9. Create tag `v3.0.0` only after sandbox/live merchant acceptance has produced a release receipt.
10. Attach the installable `open-bunq-payments.zip` generated by `tools/build.sh` to the release.

## Before wider promotion

- Run sandbox OAuth/payment tests against a real bunq sandbox account.
- Runtime-test supported WordPress/PHP/WooCommerce/SureCart combinations.
- Have at least one independent code/security review.
- Decide WordPress.org naming/trademark policy if submitting to the plugin directory.
- Add screenshots and translations only after UI stabilizes.

## Repository secrets

No bunq/SureCart credentials belong in GitHub Actions secrets merely to run static CI. If future integration CI uses test credentials, use dedicated sandbox credentials, least privilege and protected secret environments.
